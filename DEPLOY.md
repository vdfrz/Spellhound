## Credentials and launch

The builder flow in [Publik’s app-token instructions](https://publikhq.com/skills/api.md) uses a human-approved, short-lived device authorization to mint the app token for a specific slug. A listing may first require the repo owner to claim it. This is a builder action, separate from the user's browser claim. Do not run the publishing flow to unlock a private pilot. If a private token is unavailable, stop here.

The pilot runtime reads only the server environment variable PUBLIK_APP_TOKEN for provisioning. Never use a shared personal AI key. Do not put tokens in manifests, Docker layers, chat, browser bundles, URLs or logs. On replacement, update the runtime secret and restart; verify a **fresh** private installation. Confirm old-token invalidation and existing-key behavior with Publik: issuing a replacement is not proof of revocation. If an installation key is revoked, the next wallet check invalidates the local session. Sign-out deletes that server credential; it does not claim to revoke the upstream credential or sign the browser out of Publik.

Build with Node 22 or later, npm ci, npm test and npm run build. The Dockerfile serves the build and its manifest from the same Node process. Start with npm start only on the approved runtime: SPELLHOUND_ORIGIN must be the externally accessible HTTPS origin with no path, query or credentials. TLS must terminate at its ingress. Use a dedicated private session volume outside dist at SPELLHOUND_SESSION_DIR (default /data/spellhound/sessions), writable only by the service. Use a single process for this pilot; budget/rate-limit installation creation at the ingress as well. The process binds PORT (default 8080); SPELLHOUND_BIND=127.0.0.1 is available for local checks. Do not log request bodies, cookies, upstream keys or access-bearing links. Scope access at ingress to the pilot group; knowing the URL is not an invitation check.

The install page at / links to /manifest.xml. The server renders it from the template using the configured origin even inside the built image. For a separate XML handoff, run npm run manifest -- "$SPELLHOUND_ORIGIN" after building; retrieve dist/manifest.xml. The repository template and developer manifests are not release artifacts.

## Private pilot acceptance

1. Visit / on the **confirmed Publik-operated host**. Confirm its identity and the current manifest’s Word ribbon command, pane URL and icon URLs. Make a blank document in a dedicated test profile. WordApi 1.6 is required; the organization must permit add-ins. For a managed Windows tenant, the administrator can assign the reviewed manifest to a small test group.
2. If using Iris, give it the install guide, not the claim link: “Help me install this pilot XML into Word. Stop when Spellhound opens; I’ll do sign-in and payment.” Pause screen sharing or observation before entering credentials. Use the Microsoft instructions linked above for the actual upload or Mac folder. An ordinary browser visit cannot install an Office add-in.
3. Open the ribbon command. Verify the only login is Publik. Click the browser link, claim the installation, return to the pane. It polls every three seconds for up to ten minutes. Test Mac and Windows Word, plus Word for the web with its partitioned cookies; retry with cookies blocked, stale tabs and an unavailable wallet. No document features should open on failure.
4. Test a funded wallet, an empty wallet, adding credit and BYOK. No provider request should bill the Publik wallet until the user connects it. With a dedicated test key, confirm a synthetic request is billed only to the selected provider; never use a private document. The pilot uses the balanced tier for contract reasoning. Browser-direct providers depend on CORS, endpoint permissions and organization policy.
5. With two accounts, two installations and two open panes, test no cross-install chat history, keys, local clauses or spending. Reopen on a second device: sign in again, expect **no sync**. Sign out, revoke a test install in Publik, and check server expiry. A fresh claim after expiry gets a new local namespace. Old browser data may remain on disk; use a dedicated profile and clear its site data after the pilot. Document-embedded Word content remains in the file.
6. Usage reports are off until enabled and can be disabled in Account. Confirm only app_opened and active_session (every 30 minutes while visible) with a random install ID, version, app slug and actual supported OS. The server sends them with the install credential, never the BYOK key or document. DNT and the operator’s DO_NOT_TRACK / PUBLIK_TELEMETRY settings suppress forwarding. No promise of fellowship credit: Publik documents restrictions on web-app counts. Opting out does not turn off wallet checks or billing for actual AI calls.
7. Record observed platform, build, result and sanitized status codes only. If any required step fails, retain the draft and do not distribute. Uninstall the pilot manifest via Word or remove its Mac wef copy; remove the test profile/site data and dispose of test credentials with Publik.
